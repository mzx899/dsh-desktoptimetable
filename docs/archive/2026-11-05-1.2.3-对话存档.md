## 1. 用户反馈

1. 「已完成的事项是不是还不能进行全部删除？」
   —— 复核后确认：**全部删除本身正常**（用户随后确认「全部可以删除」）。
2. 「现在点击折叠好像只能张开不能收缩」
   —— 真实缺陷：展开「已完成的提醒事项」后，再点这一行收不回去。

## 2. 根因

`UI/CompletedRemindersRow.swift` 里的 `HeaderButton` 重写了 `hitTest(_:)`，
想让整行（标题 / 副标题 / chevron）都能点，但写成了：

```swift
override func hitTest(_ point: NSPoint) -> NSView? {
    bounds.contains(point) ? self : nil
}
```

`hitTest(_:)` 收到的 `point` 是**父视图坐标系**，不是按钮自己的 bounds：

- 收起时 header 在 row 里 y=0，父视图坐标碰巧和本地坐标一致 → 能点中；
- 展开后 row 变高，header 移到 y=334（row 是非翻转坐标系）→
  `bounds.contains(point)` 判成「点在按钮外」→ 按钮收不到 action；
- 点击落到 `CompletedRemindersRow` 本身，所以**看起来只开不合**。

## 3. 修复

- 先把 point 从父视图坐标转换到本地，再判断 `bounds`：

```swift
override func hitTest(_ point: NSPoint) -> NSView? {
    guard let parent = superview else { return super.hitTest(point) }
    let local = convert(point, from: parent)
    return bounds.contains(local) ? self : nil
}
```

- 同样修了 `UI/DayPanelSettingsRow.swift` 里 `DayPanelListRow.hitTest` 的同款坐标系错误。
- 整行点击区保持不变（标题 / 副标题 / chevron 都算）。

## 4. 回归（真实点击，不是直接调 action）

`--verify-completed-reminders` 新增三段真实 `NSEvent` 点击：

1. 展开状态下点标题行 → 必须收起；
2. 再点标题行 → 必须重新展开；
3. 点「全部删除…」→ 确认流程必须被触发（自检用 hook 拦下弹窗，不真的弹）。

自检会打印每次点击的命中视图（`HeaderButton` / `NSButton`），
点不中时能直接看出落到了谁身上。目标在面板滚动区外时先
`scrollToVisible`，避免自检误判成「点不到」。

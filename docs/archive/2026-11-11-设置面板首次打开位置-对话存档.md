## 2. 根因

`SettingsWindowController.buildWindow()` 的**最后两行**：

```swift
window.makeKeyAndOrderFront(nil)
window.orderFrontRegardless()
```

新窗口建出来时 origin 是 **(0, 54)**，而这两行**把窗口直接摆到了前面** ——
面板以左下角的姿态**上屏了至少一帧**。
`show()` 里的 `positionWindow` 是**之后**才跑的（它按 `resetToHome` 之后的最终尺寸校准位置），
于是用户看到「先在左下角、再跳到中间」。

**为什么第二次打开正常**：`buildWindow()` 不再跑，窗口早已在正确位置。

前两轮为什么没修好：
- 轮次 1（条目 4）：只把 `positionWindow` 提前 —— 但 `buildWindow()` 末尾那次
  `orderFront` **更早**，面板还是先在左下角上屏了。
- 轮次 2（条目 7）：`isRestorable = false` + orderFront 后再摆 + `windowDidBecomeKey` 兜底
  —— 三条都是**事后纠正**，管不住「第一帧就在左下角」。

---

## 3. 修

### 3.1 上屏之前先摆位（主修）

`buildWindow()` 里，`orderFront` **之前**调一次 `positionWindow(mouse: nil)`
（纯几何，很便宜）：

```swift
positionWindow(mouse: nil)
recordFirstVisibleFrame()          // 自检用（见 §4）
window.makeKeyAndOrderFront(nil)
window.orderFrontRegardless()
```

`show()` 里原来那次 `positionWindow` 保留 —— 它按 `resetToHome` 之后的最终尺寸再校准一次。

### 3.2 顺带修掉一条自引用锚点（隐藏 bug）

`AppDelegate.installWindowAnchor()` 里的规则：

```swift
if let settings = self.settingsController,
   let w = settings.window, w.isVisible, w.isKeyWindow {
    return NSPoint(x: w.frame.midX, y: w.frame.midY)   // ← 设置面板自己的中心
}
```

这条规则是给「**从设置面板里弹出来的窗口**」用的（2026-11-10 加：课表折叠时写日记的窗口
不该塞进折叠条中间）。但它有个副作用：**面板自己拿到 key 之后**，
`WindowAnchor.provider()` 返回的就是**它自己的中心** →

- `positionWindow` 再怎么调都不会动（自己跟自己比，偏差恒为 0）；
- 轮次 2 加的 `windowDidBecomeKey` 兜底**恒为 0，永远不触发** —— 是**死代码**。

修法：新增一条**只认课表**的取值器 `cardAnchor()`：

- `SettingsWindowController.cardAnchorProvider: (() -> NSPoint?)?`（可注入，便于自检）；
- `SettingsWindowController.cardAnchor()` —— 有接线就用接线，没接线退回**主屏可见区中心**
  （和 `WindowAnchor.provider` 的默认值一致，不至于把面板摆到 (0,0)）；
- `positionWindow` 与 `windowDidBecomeKey` 都改用它 → **`windowDidBecomeKey` 的兜底现在是活的了**。

**接线位置很关键**：`AppDelegate.buildSettingsController()` 里
（**不是** `installWindowAnchor()`）—— 后者调用时 `settingsController` 还是 nil，
`settingsController?.cardAnchorProvider = …` 会被 `?.` **静默跳过**。

---

## 4. 自检

新增 `--verify-settings-first-open`：

- 新增 `SettingsWindowController.testFirstVisibleFrame: NSRect?` +
  `recordFirstVisibleFrame()`；
- 记录时机：**`orderFront` 之前**（之后位置已被摆正，看不出问题）；
- 断言 4 条：
  1. 第一次上屏时面板中心贴着锚点（容差 2pt）；
  2. 第一次上屏时**不落在屏幕左下角**（离左边缘 < 40pt 且离下边缘 < 40pt）；
  3. 整个窗口在屏幕可见区内；
  4. 关掉再打开位置不漂。
- 已登记进 `AutomationMode.automationFlags`（`Tests/main.swift` 有一条断言盯着这个）。

### 4.1 验证它**真的能抓到这个 bug**

临时把 `positionWindow` 挪回 `orderFront` 之后：

```

  锚点（主屏中心）   = (756.0, 501.5)

❌ 第一次可见时面板落在屏幕左下角（frame=(0.0, 54.0, 580.0, 152.0)，屏幕=(0.0, 54.0, 1512.0, 895.0)）
```

恢复修复后：

```

  锚点（主屏中心）   = (756.0, 501.5)
✅ 设置面板第一次打开的位置（不在左下角）：通过
```

## 1. 需求时间线

### 1.1 日期覆盖层

**用户需求**：点课表表头的日期（"周一 / 3"），在该列上覆盖一个面板，
显示当天课程 + 系统提醒事项（可增删改）+ 系统日历事件；
再点一次同一列日期关闭，拖动课表时强制收起。

**实现结果**：

- 覆盖层做在网页层（`Resources/Timetable.js` / `Timetable.css`）：
  只覆盖那一列、表头不被遮住；顶部实心、尾部用 `mask-image` 渐隐淡出；
  打开 600ms `clip-path` 揭开，收起 400ms 收拢。
- 面板内容是**逐条玻璃卡片**：待办 / 日程 / 今日详情 / 空状态 /
  「＋ 添加待办」幽灵卡；内容装不下时在面板内滚动，不截断、不统计条数。
- 数据由原生 `DayPanelController` 查询 EventKit 后推给网页；
  网页发 intent（`datePanelOpen` / `todoToggle` / `todoAdd` / `todoDelete`）。
- 自动化模式下注入 fake EventKit store，绝不请求真实权限、绝不碰真实日历 / 提醒。

### 1.2 表头标记与高亮

**用户需求**：表头要能看出哪天有待办 / 日程；正在查看的那一列要有高亮。

**实现结果**：

- 蓝点 = 今天（星期几右边），红点 = 有待办、橙点 = 有日程（星期几左边），
  红 / 橙可同时出现；大小和间距与蓝点一致。
- 选中列在**原位**加蓝色渐变底 + 外发光 + 顶部亮线，
  不从表头行里拆出来（拆出来会让 CSS Grid 对齐崩掉）。

### 1.3 待办可写 + 清单选择

**用户需求**：在覆盖层里勾选完成、添加、删除待办，并写回系统「提醒事项」。

**实现结果**：

- 单击圆圈标记完成、右键删除、点「添加待办」展开内联输入框。
- 新待办写进设置里选的清单，默认新建「桌面课表」；
  设置面板新增「日期覆盖层」卡片：接入开关（默认关）、清单选择、天气开关（默认关）。
- 写回成功后的第一次 EventKit 取数可能是旧快照 —— 用「刚完成 / 刚删除 / 刚新增」
  三张本地事实表在取数追上之前过滤，避免条目复活或闪一下。
- 翻周时给 `refreshAll` / `loadContent` 加令牌，旧一轮晚到的结果直接丢弃。

### 1.4 今日详情：农历 / 节气 / 节日 / 天气 / 宜忌

**实现结果**：

- 农历、节气、节日离线计算；`AlmanacCalendar` 按建除十二神给出宜 / 忌
  （简化的氛围提示，不是权威老黄历）。
- 天气：CoreLocation 系统定位 + Open-Meteo，无 API key、不做 IP 推断；
  设置里默认关，拿不到就隐藏整行，绝不显示假数据。

### 1.5 表头闪烁与周几 / 日期对齐

**用户需求**：点日期、点完成时表头会「一暗一亮」；周几文字和日期数字没对齐。

**实现结果**：

- **闪烁根因**：原生推送的数据没变，但 `JSONSerialization` 的字典键顺序每次不同，
  网页用 `JSON.stringify` 算出来的指纹就变了 → 整棵树重建 → `.sel` 落到新节点上，
  200ms 颜色过渡重播。改成键序无关的 `stableText()` 指纹；建表头时就把 `.sel`
  写进初始 class，双保险。
- **对齐**：蓝点以前只在「今天」那一列渲染，左右间距也不对称。
  现在两个点都保留占位（不显示时只 `visibility: hidden`），`gap: 3px`，
  七列文字中心与日期数字中心逐像素对齐。

### 1.6 系统提醒事项改完，课表面板不更新

**用户需求**：在系统「提醒事项」里勾完一条，红点没了，但课表面板里该条目还在。

**实现结果**：

- 网页按天缓存面板内容；原生在面板关着时只重算红点，网页缓存仍是旧的。
- 新增 `dayPanelRevision`：`EKEventStoreChanged`（0.4s 防抖）后版本号 +1 并推送；
  网页看到版本号变化就作废按天缓存、重新请求当前天。
- 自检里模拟系统变更，确认网页确实重新发了 `datePanelOpen`。

### 1.7 版本归档与更新记录

**用户需求**：把这个版本变成 1.2.0 放到版本迭代里。

**实现结果**：

- `Makefile` 的 `VERSION` → `1.2.0`；按小版本惯例换 bundle id：
  `com.desktoptimetable.app.v110` → `com.desktoptimetable.app.v120`
  （可用 1.1.5 并存；数据目录不变）。
- `Info.plist` 显示名 / 版本 / bundle id / URL name 全部对齐。
- 构建归档到 `版本迭代/DesktopTimetable-1.2.0.app`，Info.plist 校验为 1.2.0，
  `codesign` 为 ad-hoc 签名。
- `CHANGELOG.md` 新增 `[1.2.0] - 2026-11-04`；`README.md` 与
  `docs/下一轮对话提示词.md` 同步当前版本。

### 1.8 时钟停在半小时前（归档后补修）

**用户反馈**：课表上显示的时间是半小时以前的，点一下「下一周」就恢复正常。

**根因**：

- 时钟 / 状态条只在整树 `render()` 里计算；原生虽然每分钟推一次状态，
  但数据本身没变 → `tableStateKey` 判成「没变」→ 走轻量路径，顶部不重画。
- 指纹里原先塞了 `Math.floor(Date.now() / 60000)` 想靠「跨分钟」触发重绘，
  但新旧两个指纹是**同一时刻**算的，分钟项永远相等 —— 这行从没起过作用。
- 之前键序抖动会偶然触发整树重绘，把这个问题掩盖了；表头闪烁修好后，
  时钟就稳定地停在最后一次真正重绘的时刻。

**实现结果**：

- 新增 `updateLiveTexts()`：每 10 秒就地更新 `.clock .tnum` / `.tdate`
  和 `.status .stxt` / `.smeta`，并切换「正在上课」的 `.live` 状态，
  **不重建 DOM**；页面从后台回来时也立刻对一次表。
- 时钟 / 状态条文字抽成 `liveTickerTexts()`，`render()` 与定时器共用一份逻辑；
  当日上下文由 `liveContext()` 按 `render()` 的口径现算。
- 跨天时表头的「今天」蓝点要移动 → 检测到日期变化时调一次整树 `render()`。
- 指纹里删掉无效的分钟项。
- `--verify-web-render` 新增回归：把时钟改成 `00:00` → 调就地刷新 →
  必须对回当前时间；并检查定时器是否装上。

### 1.9 空闲耗电：呼吸圈与悬停同步

**用户反馈**：现在的耗电量大不大，有没有什么地方能在一切不变的情况下，
减少 CPU / 内存占用和耗电。

**发现**：

- 状态条呼吸圈用的是无限的 `box-shadow` 动画。`sample` 显示 WebContent
  约 10% 的 CPU 花在逐帧重绘 / 更新事件区域上，主进程另有约 5% 花在接收
  每帧的 layer tree 提交上 —— 空转时两者合计约一个核心的 15%。
- 指针在卡片外移动时，全局鼠标监控每一帧都会调一次
  `evaluateJavaScript` 去清悬停态，哪怕网页里早就没有悬停。

**实现结果**：

- 呼吸圈拆成 `.pulse::before`（放大 + 淡出的圆盘）和 `.pulse::after`（圆点），
  动画只改 `transform` / `opacity`，由合成器插值；圆点盖住圆盘中心，
  露出的圆环与原来的 `box-shadow` 版本一致。
- `clearLiveHover` 加去重：只有上次真的同步过悬停才发一次 JS。
- `--verify-web-render` 加省电回归（伪元素动画、21×21、`.pulse` 无 box-shadow）；
  `--render-day-panel ... pulse-demo` 可以把呼吸圈钉在 40% 相位截图核对。
- 实测空闲 CPU（30 秒采样，占一个核心的比例）：WebContent 10.2% → 0.15%，
  主进程 4.6% → 0.55%。内存没有变化（仍主要由 WKWebView 本身占用）。

## 3. 验证记录

- `make test`：**全部通过（1839 项断言）**。
- `--verify-day-panel`：农历 / 锚点 / 状态机 / EventKit / 自动化护栏，
  使用 fake store，不触发真实 TCC 权限框。
- `--verify-day-panel-click`：真实 WKWebView 点击（添加待办 / 圆圈完成）；
  回归检查原生推送不重建表头节点（id 稳定、`changed: false`、`.sel` 保留）、
  七列表头中心与日期数字中心一致、系统数据变化后重发 `datePanelOpen`。
- 所有自检都用 `DT_DATA_DIR` 指向临时目录，不碰真实课表。
- `--verify-web-render` 呼吸圈省电回归：`pl-idle`、伪元素 21×21、box-shadow=none；
  出图核对用 `--render-day-panel ... pulse-demo`。
- 空闲 CPU 实测量见 1.9（WebContent 10.2% → 0.15%，主进程 4.6% → 0.55%）。
- 构建后从 `build/DesktopTimetable.app` 重启应用；归档版 Info.plist 为 1.2.0。

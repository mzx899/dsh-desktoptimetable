## 1. 用户反馈

> 「当修改某一列的待办事项和点击了添加待办事项之后，要是鼠标不小心移动到别的列了
> 之后，原本要输入的那一列还是会显示，就是把它固定着，以免鼠标误滑动。」

即：正在输入时，鼠标一滑到别的列，正在输入的那一列就没了（换列 + 内容被重建）。

## 2. 根因

日期覆盖层是**跟随指针**的（点开一列之后，指针移到别的列就换列）：

- `Resources/Timetable.js` 的 `onPointerMove` 里，`DP.day !== day` 就 `openPanel(day)`；
- `openPanel` 会**重建整块内容**（`buildPanel` / `renderPanel`）→ 正在输入的
  `<input>` 被销毁，打了一半的标题 / 时间直接丢；
- 之前只处理了「指针离开卡片」：`DP.adding` / `DP.editingTodoKey` 为真时
  `onPointerLeave` 不 `fadeOutPanel`（1.2.2 加的）—— **没处理「指针在卡片内换列」**。

## 3. 修复

`onPointerMove` 在菜单判断之后加一条短路：

```js
if (DP.adding || DP.editingTodoKey) {
  DP.hoverDay = DP.day;   // 状态也别自相矛盾
  return;                 // 不换列、不淡出
}
```

覆盖的两种输入态：

| 交互 | 状态标记 |
|---|---|
| 点「＋ 添加待办」，输入框展开 | `DP.adding = true` |
| 右键待办 →「修改…」进入卡片内编辑 | `DP.editingTodoKey = <key>` |

细节：

- **锁的是「移动」，不是「点击」**：点别的列表头仍然是主动换列
  （明确意图，会放弃正在输入的内容）；
- Esc / 回车提交后 `adding` / `editingTodoKey` 归零 → 跟随立刻恢复；
- 指针滑出卡片时的「不收起」沿用 1.2.2 的行为，两者一起构成完整的输入保护。

## 4. 自检

`--verify-day-panel` 新增 `4c-13d-2`，用真实 DOM 事件驱动 `onPointerMove`
（坐标取自 `.hcell[data-day]` 的实际 `getBoundingClientRect()`）：

1. **编辑态**：`ttDayPanelOpen(3)` → `ttDayPanelTodoMenuAction('edit', {key:'id:edit-1'})`
   → 指针移到第 2 列 → 面板仍停在第 3 列、`editingTodoKey` 没被重置、
   已输入的标题仍为「原标题」；
2. **解锁**：Esc 取消编辑 → 再移到第 2 列 → 必须**真的换到第 2 列**
   （只验「锁住」的话，把跟随彻底关死也能通过）；
3. **添加态**：`ttDayPanelOpen(3)` → 点 `.dpadd` → 指针移到第 6 列 →
   面板仍停在第 3 列、输入框还在；
4. **解锁**：Esc 取消添加 → 再移到第 6 列 → 必须换到第 6 列。

自检结束会把面板恢复到第 3 列，后面的用例（`4c-13e-2`「表头上方不收起」）
依赖这个状态。

## 1. 「一直闪」是两件事叠在一起

### 1.1 先做了一个真机诊断开关

`DT_FLICKER_DIAG=1` → 打开网页侧探针（`window.__ttEnablePanelTrace`）：
每次 `renderPanel` **真正重建**（指纹变了才重建）就 `post('panelTrace')`，
原生写一条 `DiagLog`；面板 class / 高度 / 实心区高度 / 透明度 / 滚动位置变化再写一条。

真机日志（用户实际点完成那一段）：

```
22:02:34.100 完成写回 id=6EA5… 结果=成功
22:02:34.147 覆盖层重建 n=73 卡片=7 pending=…:done
22:02:34.598 覆盖层重建 n=75 卡片=6      ← 少一张
22:02:35.491 覆盖层重建 n=79 卡片=7      ← 又回来
22:02:41.639 取数 day=3 原始待办=5 显示=1
22:02:42.094 覆盖层重建 n=86 待办=1
```

打开一列之后的 4 秒里重建了 **15 次**；`卡片` 数在 **6 ↔ 7** 之间来回跳。
那张 6 和 7 之间跳的卡片就是 `.dpdigest`（琥珀色「今天 N 条待处理 · 逾期 M 条」）——
用户说的「黄色待办事项」。

### 1.2 根因 A：渲染指纹受 JSON 键序影响

`renderPanel` 用 `JSON.stringify([day, data, …])` 和上一版比。原生推来的是
Swift `[String: Any]`，序列化成 JSON 之后键序不固定 → 内容一样也判「变了」→
**每推一次就整块重建**（半透明玻璃面板闪一下）。

修：`stableStringify()`（对象按键名排序）做指纹。

### 1.3 根因 B：摘要卡的 nil 中间态

`loadContent` 无条件 `content.todoDigest = nil`，然后：

1. 推一版「没有摘要」→ 摘要卡消失、下面卡片整体上移；
2. 0.35 秒后 `refreshTodoDigest` 的异步回包回来 → 推一版有摘要 → 卡片出现、整体下移。

一次刷新上下跳两下。修：只有 `resetImmediately`（换天 / 换列）才清空，
同一天刷新保留旧值等新值替换。

### 1.4 自检：`--verify-complete-flicker`（新）

- `FakeEventKitStore`（`appliesToggle` + `toggleDelay 0.12` + `simulateStaleReads 2` +
  `overduePendingCount 1` + `overdueDelay 0.3`）复现真实写回链路；
- 真实鼠标事件点圆圈（`NSApp` → `CardInteractionView` → `forwardClick`）；
- 之后 4 秒按 100ms 采样：待办 key 序列、**全卡片序列**（含 `todo-digest`）、
  重建次数、面板 class / 高度 / bodyH / 滚动位置；
- 断言：不回弹、重建 ≤ 6、摘要卡出现后不能消失、键序不同的同内容推送不能重建。

**两条都验证过能抓到 bug**：
- 摘要卡修复临时改回 → `❌ 摘要卡出现之后不能消失再回来（实际消失 1 次）`
- 指纹临时改回 `JSON.stringify` → `❌ 内容相同、只是 JSON 键序不同的推送不能重建面板（实际 1 → 2）`

⚠️ 踩坑记录：`--verify-complete-flicker` 第一次忘了登记进
`AutomationMode.automationFlags`，那几次以**非自动化模式**运行 →
`reloadData()` 走到 `refreshReminderSchedule()`，**可能清掉了用户已经排好的上课提醒**。
已登记；用户重启 app 会自动重排。

## 2. 打开设置 → 覆盖层自动收回

`AppDelegate.openSettings()` 第一件事：

```swift
if let state = dayPanel?.testState, state.open, let day = state.day {
    dayPanel?.close(day: day)
}
```

原生清 `currentDay` + 推 `dayPanelOpen: false`，网页 `ttUpdate` 里已有这条处理
（`closePanel(true)`，播 400ms 收起动画）。

自检 `--verify-settings-closes-panel`（新）。
⚠️ 踩坑：一开始直接在 `--verify-day-panel-click` 里调 `delegate.testOpenSettings()`，
崩在 `settingsController` 隐式解包（`prepareForRendering()` **不建** settingsController，
要用 `prepareForImportVerification()`）；而且那个自检里已经进过「文本输入模式」。
所以拆成独立自检。

**验证过能抓到 bug**：去掉那三行 → `❌ 打开设置之后日期覆盖层必须收起来（open=1）`。

## 3. 天气不再请求定位

用户原话：「打开了显示天气的选项，还是会跳出来桌面课表想使用你当前的位置的请求授权的窗口」。

三处：
1. `SettingsWindowController.dayPanelWeatherToggled`：删掉 `requestLocationAccess()` 调用
   （`DayPanelController.requestLocationAccess` 整个删掉）；
2. `DayPanelController.loadWeather`：**没选地区直接 `finishWeatherRequest([:])`**，
   不再走「按当前定位取预报」（`fetchForecastAtCurrentLocation` 删掉）；
3. `OpenMeteoWeatherProvider.requestCurrentLocation`：加总闸 `allowsSystemLocation`
   （只有 `DT_WEATHER_PROBE=1` 诊断探针才允许真定位），其余一律 `completion(nil)`。

自检：
- `make test` 新增 suite「天气 · 不再请求定位授权（只用手填地区）」：
  无地区 → `requestCurrentLocation` **0 次**；有地区 → 仍 0 次但取了一次预报；
- 静态体检：源码里不能再出现 `requestLocationAccess()`、「按当前定位取预报」，
  provider 必须先判 `allowsSystemLocation`。
- `--verify-day-panel` 的天气用例原来靠「空地区 → 走定位」拿天气，已改成显式 `weatherCity: "秦皇岛"`；
  另外单独用「无地区」controller 验 `region == ""` 且 **0 次定位请求**。

## 4. 不点击也实时刷新 / 上下课边界立刻更新

卡片顶部时钟 / 状态条本来就是网页 `setInterval(updateLiveTexts, 10000)` 自己走
（不依赖点击）。这次补**边界精确定时器**：

```js
function scheduleBoundaryTick(now) {
  // 找下一个 blockStart / blockEnd（分钟），setTimeout 到那一刻 + 300ms
}
```

`updateLiveTexts()` 末尾调用，每次重排；平时仍 10 秒一次，边界处几乎不晚。

自检（`--verify-web-render` 扩展）：
- 注入了「今天、每个 block 都上」的课；
- 采样：`S480=正在上课 · 边界测试课0 | E574=正在上课 | E575=下一节 | … | E1215=今日课程已结束`；
- 新增断言「**上课开始那一刻必须是「正在上课」**」。

⚠️ 踩坑：注入代码里写了 `S ? S.semesterStart : …` —— `S` 是网页模块内变量，
IIFE 里没有 → ReferenceError → 注入永远失败（这个自检长期**假绿**：`sawLive` 断言
只是碰巧在白天跑过）。已改成写死 `currentWeek: 1, viewWeek: 1`。

顺带修了 `--verify-day-panel` 的 7 条长期红：
- 「填满两位自动跳栏」两条 —— 该行为当天早先已被用户要求删掉，断言过时 → 改成打印读数；
- 「回车提交 / 非法时间提示」5 条 —— 测试脚本用 `document.activeElement` 派发 Enter，
  自动跳栏删掉之后焦点停在 body → Enter 发不出去 → 恒假。改成显式 `m.focus()` 再派发。

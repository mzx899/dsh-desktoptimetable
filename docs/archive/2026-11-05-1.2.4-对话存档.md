## 2. 用户反馈的问题

> 「点了 App，课表很久不出来，鼠标放在课表范围里也不显示，点很多次、等很久才出来。」

用户的外观配置（真实 `config.json`）：

```json
{ "fadeInSec": 3, "fadeOutSec": 3, "minOpacity": 0, "maxOpacity": 1 }
```

`minOpacity = 0` → **不悬停时课表完全透明**。所以「没出来」= hover 判定一直是 false。

## 3. 根因（有真机实测数据）

三个事实叠在一起：

1. 课表窗口层级是 **`-1`**（`AppDelegate.buildDesktopWindow`）：
   普通窗口（0）之下、桌面窗口（≈ `-2147483623`）之上。
   `DesktopWindow` 初始化时还写着 `desktopIconWindow + 1`，两处口径不一致。
2. `NSWindow.windowNumber(at:belowWindowWithWindowNumber: 0)` 报回来的窗口号
   会随「课表当前是否可见」而变 —— 课表还没亮（alpha = 0）时它给的是
   **比课表还低**的桌面图标窗口（实测，见下）。
3. 旧判定把「不是我们的窗口」一律当成遮挡：

```swift
let coveredByOtherApp = topNumber != 0 && !isOwnWindow(topNumber)   // ⚠️ 桌面窗口也算
```

真机实测（`DT_HOVER_DIAG=1`，指针停在卡片矩形内）：

| 时刻 / 情形 | alpha | `windowNumber(at:)` 给的窗口 | 层级 | 旧判定 | 新判定 |
|---|---|---|---|---|---|
| 启动瞬间（还没亮，`minOpacity = 0`） | 0.00 | 访达的**桌面图标窗口** 34451 | `-2147483603` | `covered = 1` ❌ | `covered = 0` ✅ |
| 亮着，指针下面就是课表 | 1.00 | **我们自己的窗口** 40325 | `-1` | `covered = 0` ✅ | `covered = 0` ✅ |
| 亮着，指针压着 DeepSeek Harness 窗口 | 0.22 | **DeepSeek Harness 窗口** 297 | `0` | `covered = 1` ✅ | `covered = 1` ✅ |

也就是说：

- `alpha = 0` 时窗口服务器给的是**比课表还低**的桌面图标窗口，
  旧代码把它当成「被别的 App 盖住」→ 课表永远不亮 → **死锁**（本轮要修的 bug）；
- `alpha > 0` 之后，它既能报我们自己的窗口，也能报真的盖住课表的那个 App 的窗口
  （两种都实测到过）—— 所以**不能**只按「是不是我们的窗口」判，必须比层级；
- 新判定三种情况全对：桌面图标窗口不算遮挡，真的被高一层窗口盖住时仍然会淡下去。

死锁怎么破的：`revealCard` 里「先亮一下」把 alpha 拉到 1 → 窗口变得可命中
→ 之后判定才可能返回「自己 / 真实遮挡」→ 课表恢复正常。
这也解释了用户说的「点很多次、等很久才出来」。

## 4. 修复

### 4.1 遮挡判定改成按层级比较（新 `Model/HoverCoverPolicy.swift`）

```swift
static func covers(otherLayer: Int?, ourLevel: Int) -> Bool {
    guard let otherLayer else { return false }   // 查不到 → 不当作遮挡
    return otherLayer > ourLevel                 // 只有更高的窗口才挡得住
}
```

- `layer(ofWindowNumber:)` 用 `CGWindowListCopyWindowInfo(.optionIncludingWindow)` 查层级；
- `cardWindowLevel` 收成**唯一一份**（`-1`），
  `DesktopWindow` 初始值与 `AppDelegate` 最终设置都用它；
- `onScreenWindowLayers()` 给自检用（证明「桌面窗口确实更低」不是纸上推演）。

`AppDelegate` 侧：

```swift
private func isPointCoveredByOtherApp(_ number: Int, layer: Int? = nil) -> Bool {
    guard number != 0, !isOwnWindow(number) else { return false }
    let otherLayer = layer ?? windowLayer(ofWindowNumber: number)
    return HoverCoverPolicy.covers(otherLayer: otherLayer,
                                   ourLevel: window?.level.rawValue ?? 0)
}
```

- `windowLayer(ofWindowNumber:)` 带 **2 秒缓存**（`updateHover` 挂在每次 `mouseMoved` 上）；
- `pointerInCard` / `pointerOnOwnPanel` 拆成语义清晰的两个变量，
  `pointerOnCard = pointerInCard && !pointerOnOwnPanel && !coveredByOtherApp` ——
  设置面板盖在卡片上时仍然不转发网页悬停坐标。

### 4.2 启动时先亮一下 + 每 10 秒重算 hover

- `revealCard()` 渐显前先 `updateHover()`（按**当前指针位置**重算，
  不沿用初始的 `hovering = false`）；
- 先 0.35s 渐到 alpha = 1「亮一下」，0.9s 后按 hover 状态落回常态
  —— 用户能明确看到「课表出来了」；
- `startRefreshTimer` 每 10 秒 `updateHover()`：鼠标不动时收不到
  `mouseMoved`，别的窗口移开 / 关掉后状态原本永远不刷新；
- 删掉 `[TT-ALPHA]` 诊断日志，改成**按需开启**的 `DT_HOVER_DIAG=1`：
  每行打印 `p / inCard / onPanel / top(自己|别的,层级) / covered / inside / hovering / alpha`。
  本轮就是靠它把根因钉死的，留着备查（默认零开销）。

### 4.3 自检

新增 `--verify-hover`：把「指针位置 / 窗口服务器答案」喂进**真实的**
`updateHover`（层级比较 → `inside` → `hovering` 全走生产代码），
不挪用户鼠标、不真的盖窗口。用例：

1. 报桌面图标窗口 / 桌面窗口（层级更低）→ 课表**必须亮**（旧代码在这里挂）；
2. 报出更高层窗口 → 必须淡下去（策略层安全网，实测这个查询不会返回）；
3. 指针在卡片上（报自己）→ 必须亮；
4. 被「盖住」后回到卡片 → 必须**能亮回来**（旧行为会卡住）；
5. 指针离开卡片 → 必须淡下去；
6. 真机窗口列表里确实存在比课表低的窗口；自己窗口层级能被读出来。

`AutomationMode.automationFlags` 同步登记 `--verify-hover`（否则
`refreshReminderSchedule()` 的护栏不生效，自检会动真实通知中心）。

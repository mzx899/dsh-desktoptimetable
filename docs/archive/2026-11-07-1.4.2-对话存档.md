# 对话存档 · 2026-11-07 · 1.3.1 → 1.4.2（缩放边角 / 放到最大被裁 / 课表折叠 / 折叠态缩放裁切 / 刷新卡死）

## 本轮目标

用户原话：「继续修复课表放大的问题，以及放大缩小之后不能够拖动到边缘的问题」。

拆成两件事：

1. **放大问题**：设置面板里把「课表大小」调到 ≥100% 之后，整张课表发糊；
   顺带核对扩大后的尺寸 / 玻璃 / 位置。
2. **拖不到边**：缩放之后把课表往屏幕边缘拖，会在离边一段距离时停住；
   放大档甚至会被顶出屏幕（112% 时底部整条看不见）。

## 根因（两条）

### A. 松手没把「拖动用的位图放大」收尾成 pageZoom

- 拖动帧为保证窗口 / 网页同步，走 `body { transform: scale(s) }`
  （合成器放大已画好的位图）。
- `commitCardScale` 在「设置面板开着」的分支里把最终值又走了一遍拖动帧，
  **从来没有切回 `pageZoom`** → ≥100% 档一直糊，直到重启。
- 更严重：`WebCardRenderer.usesPageZoom` 是按 `viewScale` 判的，松手后
  `viewScale = 1.12`、`rectScale` 也变成 1.12，但页面实际还是 transform
  （`getBoundingClientRect` 返回的已是视觉坐标）→ 玻璃 / 中心 / 命中换算
  全都多乘 1.12。实测松手瞬间卡片中心跳 **65.7pt**。

### B. `TimetableLayout.cardRectOverride` 在缩放后是过期值

- 它只由拖动帧写入（按**当时的窗口原点**算）。松手 / 一次性重排会把窗口
  摆到别处，覆盖值却没更新。
- `DesktopWindow.move(to:)` 的夹屏用 `TimetableLayout.cardRect` →
  按过期矩形算 → 卡片离屏幕边还有 70~130pt 就被夹住，或者被顶出屏幕
  （112% 时卡片 y = -53）。

## 追加发现（同一片代码里的第三个 bug）

「缩放 → 把课表拖到别处 → 再缩放」，卡片会跳回旧位置。三个成因：

1. `cardScaleAnchorCenter`（缩放锚点）面板开着时松手**从不清空** →
   下一轮缩放沿用上一次的锚点。
2. `dragPageTopLeft`（拖动帧算 translate 的页面原点）只在 `enterDragWindow`
   里取；面板开着时窗口不动，但用户可以把课表拖走 → 下一轮沿用旧原点，
   卡片多平移一次拖动距离（实测 +120pt）。
3. `webCardCenterInWindow()` 一律返回窗口中心；面板开着时卡片可能被夹在
   画布偏一侧 → 锚点偏，缩小后被夹回画布中心（实测 62pt）。

修复：面板松手后清空锚点；新一轮缩放 `dragWindowActive = false` 重取页面原点；
`webCardCenterInWindow()` 优先用 `cardRectOverride`。
自检新增「缩放 → 拖走 → 再缩放」：中心 `(830,516.12) → (950,485.12) → (950,485.12)`。

## 追加：放到最大时右边被削

用户截图反馈「放到最大，怎么右边被削了」。

- 根因：面板开着缩放时窗口固定，卡片按屏幕夹回后偏到画布一侧；
  画布只比最大档卡片宽 ~208pt，偏出就被 WKWebView 裁
  （真实窗口实测右边被切 55pt）。
- 修复：缩放帧里窗口**跟着卡片中心走**（取整），translate 只补亚像素零头；
  口径变成「窗口尺寸不变、位置跟随卡片中心」。
- 自检：`--verify-scale-panel` 新增「70% 贴左边 → 面板里放到最大」：
  卡片窗口坐标 `(102,102,1092,872)`、右 1194 < 1296；
  网页右 1193.96、底 972.25 都在 webView 内；真实截图 113% 四边完整。

## 遗留 / 已知口径

- 网页实测卡片高度 773（原生公式同值），pageZoom 渲染后实测 772.5~772.6，
  玻璃与卡片在上下边仍差 ~1.4pt（不影响观感 / 命中）。
- 缩放帧里窗口位置会跟着卡片中心走（尺寸不变）；卡片始终在画布正中，
  所以「放到最大右边被削」这类画布裁切不会再出现。

## 追加：折叠态缩放后展开，底部被画布裁（1.4.1）

- 根因：折叠态缩放沿用「卡片中心」锚点 → 折叠条被摆到画布中间；展开按「顶边不动

- 修复：折叠态缩放锁**顶边**（窗口按顶边摆，页面 translate 仍是展开态顶边），

  顺带修首次启动默认位置把卡片顶出屏幕上沿 61.5pt（`moveToDefaultPosition`
  按 `cardRect.minX/minY` 换算）。

  （卡片 `(106,106.6,1084,864.5)` 在画布 1296×1076 内、屏幕内完整可见）；

## 追加：折叠后切周 / 加课不刷新 + 折叠按钮折线样式（1.4.2）

用户：「加了折叠功能之后，调上一周 / 下一周无法调动，加课 / 删课也不显示，
过很久才逐渐显示」+「折叠键太小了，做成折线型」。

- 刷新卡死根因：`closePanel()` 先置 `DP.closing = true`，
  而 `runCloseAnimation()` 在「没有面板元素」时直接 return，标记永久为 true →
  `ttUpdate` 的整树重画被永久跳过（只走轻量路径）。折叠每次都会
  `closeDayPanel()`，所以被折叠功能暴露。
  修复：没有面板时立刻复位 `DP.closing / DP.closingDay`。
- 按钮：18pt 小三角 → **22pt 圆角块 + CSS 折线**（`⌄`/`⌃`），负 margin 保持状态条 35px。
- 新增 `--verify-week-arrow`：真实点击箭头（100% / 113% / 折叠态），
  周次 0.8s 内变化；make test 2041；其余 10 个 `--verify-*` 全过。
- 截图：展开态「自由安排 ⌄」、折叠态「自由安排 ⌃」。
- 版本：**1.4.2（补丁版）**，bundle id 不变，归档 `版本迭代/DesktopTimetable-1.4.2.app`。

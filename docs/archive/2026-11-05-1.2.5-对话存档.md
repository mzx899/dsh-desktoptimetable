## 1. 用户反馈

> 「每一次弹出来天气的访问权和日历提醒事项的访问权的时候，鼠标移动到那个访问权的
> 窗口之上，课表就会淡出来。用户肯定是希望点击访问权的时候，课表还在。」

即：系统权限弹框弹出后，鼠标移过去点「允许 / 不允许」→ **课表淡掉甚至完全消失**。

## 2. 根因

不是 hover 判定写错，而是**弹框期间这个判定的前提不成立**：

1. 日历 / 提醒事项 / 定位 / 通知的授权框是**系统进程**弹的窗口：
   层级落在系统弹框那一档（远高于课表的 `-1`），位置常在屏幕中间；
2. 用户把鼠标移过去点按钮时：
   - 指针离开了卡片矩形 → 判定「没悬停」→ 目标 `minOpacity`；
   - 那个点还被层级更高的弹框占着 → 更确定地判成「被盖住」；
3. 用户设的是 `minOpacity = 0`、`fadeOutSec = 3` → 「淡出」= **整张课表 3 秒内彻底消失**。

也就是说：这不是「判定错」，而是「**弹框期间不该按指针状态决定可见性**」。

## 3. 修复

### 3.1 新增 `Model/PermissionPromptWatch.swift`

一个「系统权限弹框还开着」的记账器（纯状态，时间可注入，方便单测）：

```swift
PermissionPromptWatch.begin("定位")    // 弹框之前记一笔
PermissionPromptWatch.end("定位")      // 拿到授权回调销掉
PermissionPromptWatch.isHolding()      // 现在要不要把课表钉住
```

- 按**原因**分别记账（`"定位"` / `"日历"` / `"提醒事项"` / `"通知"`）；
- 日历 + 提醒事项是**并行**弹的，只回一个不能解除 —— 全部结束才解除；
- 默认最长保持 **120 秒**（用户一直不点也会自己解除，不会无限期亮着）；
- `onStateChanged` 回调给 `AppDelegate` 用来**立刻**重算 hover，
  而不是等下一次鼠标移动。

### 3.2 弹框期间课表保持可见

`AppDelegate.updateHover` 里在菜单宽限期之后再加一道短路：

```swift
if PermissionPromptWatch.isHolding() {
    inside = true        // 指针在哪、有没有被更高窗口盖住，都不影响
}
```

`buildDesktopWindow` 里接上：

```swift
PermissionPromptWatch.onStateChanged = { [weak self] _ in
    self?.updateHover(force: true)
}
```

### 3.3 接入点（三个弹框来源）

| 弹框 | 接入位置 | begin / end |
|---|---|---|
| 日历 / 提醒事项 | `Model/EventKitStore.swift` 的 `requestReminderAccess` / `requestEventAccess` | 请求前后各一次（各自的完成回调里 `end`） |
| 定位（天气） | `Model/WeatherProvider.swift` 的 `.notDetermined` 分支 + `didChangeAuthorization` | 授权回调里 `end("定位")` |
| 通知 | `UI/ClassReminderScheduler.swift` 的 `requestAuthorization` | 完成回调里 `end("通知")` |

> 已经授权的情况：系统不会再弹框，回调立刻回来 → `begin` / `end` 同一拍，
> 不会让课表莫名多亮两秒。

## 4. 自检

`--verify-hover` 新增三段（自检里**不触发真实 TCC 权限框**，只驱动状态）：

1. **接线**：`begin("定位")` 之后不喂任何假输入，课表必须**立刻**亮着
   （验 `onStateChanged → updateHover` 这条链路接上了）；
2. **保持**：弹框期间指针在弹框上（不在卡片矩形里、且该点被层级 2000 的窗口占着）
   → 课表仍然可见；指针回到卡片 → 仍然亮着；
3. **恢复**：`end()` 之后指针离开卡片 → 恢复淡出。

新增单测 `PermissionPromptWatch · 权限弹框期间不淡出`：

- 并行两框只回一个 → 必须继续保持；全部回应才解除；
- 超时自动解除（`isHolding` 看注入的 `now`）；
- `endAll()` 兜底；没记过账就 `end` 无害；
- 进入 / 退出各通知一次（并行两框只算一次）。

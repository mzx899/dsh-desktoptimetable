## 1. 需求

### 1.1 入口与展开

- 在「日期覆盖层」卡片内部新增一行，顺序：
  接入 → 提醒事项清单 → **已完成的提醒事项** → 显示天气。
- 默认**收起**、右侧 chevron、不显示数量、**不读取 EventKit**；
  副标题「查看、恢复或删除已完成的提醒事项」。
- 点击**在卡片内就地展开**（不新开窗、不跳页），chevron 变向上；
  再点收起，并作废尚未完成的读取。
- 展开只让卡片变高，由设置页现有滚动容器负责滚动，**不改窗口尺寸**。
- 接入关闭 / 未授权：行置灰不可展开；副标题
  「开启接入并获得提醒事项权限后可查看」；未授权时带「未授权」提示与
  小号「去系统设置」按钮；点击不弹 TCC 权限框。
- 原有三行的布局、宽度、字体、颜色、行距不变，新行沿用
  `SettingsCard` / 行组件样式。

### 1.2 列表

- 默认跨**所有清单**显示已完成项，每行必须显示所属清单名。
- 按完成时间倒序。
- 按标题搜索 + 按清单筛选（所有清单 / 单个清单）。
- 高度上限 260pt，超出内部滚动。
- 首屏最多 200 条，底部「加载更多」；查询与渲染异步。
- 空状态「没有已完成的提醒事项」；加载「正在读取…」；
  失败显示原因 +「重试」，不用空状态冒充成功。

### 1.3 单条操作

- 每条显示标题、清单、完成时间 `yyyy-MM-dd HH:mm`、到期时间
  （没有时「无到期时间」）。
- **恢复**：`isCompleted = false`、清空 `completionDate`、到期时间不变；
  成功后从列表消失；到期日是当前打开的面板日期时面板重新出现它；
  红点重新计算；复用 `refreshAll` / `loadContent(resetImmediately: false)`，
  不整块清空、不闪「读取中…」。
- **删除单条**：轻量确认（标题带待办名）；成功后移除并刷新日期面板。
- 写回失败：不先从列表移除，显示原因，条目保留可重试。
- 重复提醒（`hasRecurrenceRules`）：**第一版禁用恢复**，只允许删除，
  按钮旁写明「重复提醒不支持恢复」，不静默恢复。

### 1.4 全部删除

- 范围：所有清单的所有已完成项（不是当前筛选结果）。
- 展开区底部「全部删除…」；列表为空时隐藏。
- 二次确认：标题「删除全部已完成事项？」；正文写**重新统计**后的数量；
  默认「取消」，红色「全部删除」；≥50 条要求输入「删除」。
- 逐条 `remove(commit: false)`，最后统一 `commit()` 一次。
- 显示进度、禁用按钮防连点。
- 完成后清空已删项并显示「已删除 N 条」；部分失败如实报成功 / 失败数。

### 1.5 数据 & 联动

- 协议 / 真实 store 新增：跨清单读取已完成项（**completionDate 谓词**）、
  恢复、删除单条、批量删除（返回成功 / 失败数）。
- 不新增 TCC 权限类型；沿用日历 / 提醒事项 FullAccess。
- 自动化模式只用 `FakeEventKitStore`，绝不碰真实提醒事项。
- 写操作后 `dayPanelRevision` +1、重算红点、就地重载当前天；
  网页保留当前打开天的完整缓存，避免闪烁。
- 写失败时列表与日期面板都不能出现假状态。

### 1.6 确认的版本决策

- 版本号：**1.2.2**（补丁号），不是 1.3.0。
- **bundle id 沿用** `com.desktoptimetable.app.v120`：权限 / 登录项 / 通知身份延续。
- 重复提醒的恢复：第一版**禁用**。
- 未授权入口：副标题 + 行内小号「去系统设置」按钮。

### 2.3 关键实现细节

- **读取**：`predicateForCompletedReminders(withCompletionDateStarting: nil,
  ending: nil, calendars: lists)`，只取已完成项，不拉全量再过滤；
  字段含 identifier / title / listIdentifier / listTitle / completionDate /
  dueDate / isRecurring。
- **取消读取**：EventKit 无法真正取消 `fetchReminders`，沿用项目令牌做法；
  收起时 `loadGeneration + 1`，迟到回包直接丢弃。
- **搜索 / 筛选**：先按标题过滤再加清单过滤；>300 条时后台过滤再回主线程。
- **渲染**：每批 25 行追加到 `NSStackView`，重建时用 generation 作废旧批次，
  避免一次 200 行阻塞主线程。
- **恢复联动**：先清 `recentlyCompleted` / `recentlyDeleted`（否则刚完成事实表
  会继续挡住它），再 `storeRevision += 1` → `refreshAll()` →
  当前天 `loadContent(resetImmediately: false)`。
- **删除联动**：成功 id 写入 `recentlyDeleted`（挡住 EventKit 旧快照复活），
  再 revision / 红点 / 就地重载。
- **批量删除**：先按已完成谓词取目标；逐条 `remove(commit: false)` 计成功 /
  失败；最后 `commit()` 一次。`commit` 失败 → 返回 `deleted: 0` 并
  `store.reset()` 丢弃挂起删除，绝不报成功。
- **确认框**：单条用 `AlertDialogController`（destructive，默认焦点「取消」）；
  全部删除用自建 HUD 弹窗（同版式），默认焦点「取消」，危险按钮不绑 Return；
  ≥50 条时输入框内容必须正好是「删除」才启用按钮。

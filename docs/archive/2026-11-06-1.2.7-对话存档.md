## 1. 用户反馈

> 「为什么修改完成或者是点击了取消之后，鼠标移动到课表外面，课表没有消失了。」

即：编辑待办结束后，指针离开卡片，课表应该淡到 `minOpacity`（用户设 0 = 消失），
但它一直亮着。

## 2. 定位过程

1. **先确认基线没坏**：用 `DT_HOVER_DIAG=1` + 合成鼠标移动实测 ——
   没有经过待办交互时，指针移出卡片后 `inside=0 hovering=0`，alpha 从 1 正常落到
   `minOpacity`。说明 hover 主链路是好的。
2. **列出所有能让课表「强制亮着」的短路**（`AppDelegate.updateHover`）：
   - `MenuPresenter.isMenuShowing`：`defer` 保证配对，不会长期挂着；
   - `menuGraceUntil`：固定 3 秒；
   - `PermissionPromptWatch.isHolding()`：**1.2.5 新加的，上限 120 秒**；
   - `topNumber == 自己的卡片窗口` → `inside = true`（第二个嫌疑）。
3. **对上号**：1.2.5 的保持依赖「拿到授权回调才 `end`」，而
   `DayPanelController.requestAccess` 的注释早写过：日历 + 提醒事项**并行**请求时，
   macOS **有时只弹一个框**，另一个请求**永远不回调**。
   → 那一笔 `begin` 永远等不到 `end` → 课表被钉在可见状态，最长 120 秒。
   用户点「添加待办」会触发 `requestAccess()`，所以正好在待办交互之后出现。
4. 第二个嫌疑也顺手收严：窗口比卡片大 90pt（投影留白），
   旧写法把「自己的卡片窗口」整块算成悬停；虽然实际查询只在
   指针位于卡片内 / 面板上时才发，但语义不对，一起改掉。

## 3. 修复

### 3.1 每笔保持各带兜底超时（`Model/PermissionPromptWatch.swift`）

```swift
static let defaultHoldSec: TimeInterval = 10   // 原来是 120

static func begin(_ reason: String, seconds: TimeInterval = defaultHoldSec, ...) {
    ...
    let item = DispatchWorkItem {
        guard reasons.contains(reason) else { return }
        reasons.remove(reason)
        if reasons.isEmpty { holdUntil = .distantPast }
        onStateChanged?(false)      // 立刻重算亮度，不等下一次鼠标移动
    }
    expiryTimers[reason] = item
    DispatchQueue.main.asyncAfter(deadline: .now() + seconds, execute: item)
}
```

- **不再假设 `end` 一定会来**；
- 10 秒与 `DayPanelController.requestAccess` 的「10 秒没回调就不再等」一致；
- 正常点「允许」在 1~2 秒内 → `end` 立刻清除，不受上限影响。

### 3.2 请求超时一并收尾（`UI/DayPanelController.swift`）

```swift
DispatchQueue.main.asyncAfter(deadline: .now() + 10) {
    finishOnce()
    PermissionPromptWatch.endAll()   // 这一刻不再等系统回应了
}
```

### 3.3 判定收严（`AppDelegate.updateHover`）

`topNumber == 自己的卡片窗口` 不再直接 `inside = true`，改走
「卡片矩形 + 8pt 迟滞」；只有**本 App 的其它窗口**（设置面板 / 对话框）才整体算「在课表这边」。

## 7. 已知 / 未做

- 保持上限 10 秒是权衡：如果用户在权限框上停留超过 10 秒，
  课表会先淡下去（点「允许」本身不受影响）。想更久可以调
  `PermissionPromptWatch.defaultHoldSec`，但**别回到 120 秒**。
- 卡片边缘外 **8pt 迟滞带**是刻意的防抖（1.2.7 从 14pt 收到 8pt，让「移出去」更跟手）：
  指针刚出卡片一点点时不立刻淡出。
  如果觉得「移出去还亮着」的范围太大，可以调小 `AppDelegate.hoverHysteresis`。
- 仍可继续做的候选：主题 / 背景色系统（建议 1.3.0）、本机签名证书
  （重建后重复弹权限框的根因；顺带能减少上面这类权限流程）。

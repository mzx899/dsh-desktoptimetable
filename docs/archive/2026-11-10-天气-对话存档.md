# 2026-11-10 · 天气功能补齐（对话存档）

## 本轮目标

用户原话：

> 「完成天气功能，要求有数据的显示天气数据，没有的就显示暂无数据，
> 每天过12点了就更新，理解了吗」

拆成三条可验收的行为：

1. 有天气数据 → 日期覆盖层「今日详情」里显示现象 + 温度；
2. 没有数据 → 开着「显示天气」时显示**「暂无数据」**（不隐藏、不编 0°）；关着则整行不显示；
3. 过了 12 点 → 自动换成新一天的天气（开着面板也换）。

## 根因（为什么以前“就是不显示”）

1. **生产路径没注入数据源**：`AppDelegate.buildDayPanelController` 建
   `DayPanelController` 时没传 `weatherProvider:` → `loadWeather` 直接 return。
   只有自检里手写注入 `FakeWeatherProvider` 的用例能看到天气。
2. **拿到也会被网页覆盖**：`loadWeather` 只写 `content.festival.weather`，
   而 `pushState` 的 `dayFestivals` 来自 `festivalByDay`（没有天气）。
   网页 `panelDataFor()` 会用 `dayFestivals[day]` 覆盖 `dayPanel.festival`
   → 天气又被盖回 null。
3. **没有跨天刷新**：`todayIndex` 是 `let`；天气缓存只按经纬度存 30 分钟
   → 23:55 取到的“今天”在 00:05 还会命中，显示昨天的最低 / 最高温。

# 同日第二轮（19:00）· 天气准不准 + 定位到底能不能用

## 用户原话

> 「现在的天气功能是卡在哪里了」
> 「必须要手动填写吗」
> 「现在我苹果默认天气的最低温是 0，最高温是 11」

## 结论（两件事，都实测过）

### 1）数据窗口卡在「今天起 7 天」

面板 7 列是「本周一到周日」，请求却是 `forecast_days=7`（今天起）。今天周二时，
周一那列必然落在窗口外 → 「暂无数据」；翻到下周整片空。控制器探针实测：
`PUSH 1=nil 2=晴/5.8 3=晴/8.6 …`（第 1 列 = 11-09 无数据）。
修法实测可行：`past_days=7&forecast_days=16` 能返回 23 天（11-03 → 11-25）。

### 2）系统定位在本机是死的（不是代码问题）

- `security find-identity -v` = **0 个**签名身份，`make app` 用 `codesign --sign -`（ad-hoc）；
- 最小实验 app（前台 + 正规 bundle + `NSLocationUsageDescription` + ad-hoc 签名）：
  `requestWhenInUseAuthorization()` → `start=0`，**2 秒后 `auth=3`（denied），无任何弹框**；
- 系统定位服务本身是开的（`locationServicesEnabled = true`），所以不是设置问题；
- IP 定位也不可用：开着 Clash Verge，实测出口 IP 在洛杉矶。
  ✅ 所以「手填城市」是当前唯一可靠路径（`settings.json` 的 `weatherCity`，填一次就记住）。

### 3）高低温偏 5°（本轮修掉的）

`best_match` 在秦皇岛挑到偏冷模型：实测 -5.1/5.8，参考（中国天气网 `hidden_title`
「11月10日20时 周二 晴 -1/11°C」）与苹果天气 0/11。改成
**ecmwf + gfs + ukmo 三模型取中位数**后为 -2.1/10.4。

- `CHANGELOG.md` / `README.md`：本轮条目 + 天气数据源说明。

  北京 0/15 → 0.2/12.0 → **0.8/11.5**；
  上海 10/18 → 6.4/13.3 → **9.4/14.0**。

1. 请求只取 `forecast_days=7`（今天起），面板 7 列是周一到周日 → 今天之前的列全在窗口外；

**复现脚本**（控制器级、临时目录）：`打开今天 → 切周一 → 切回今天`，
